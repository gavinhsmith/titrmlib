# titrmlib — notes for coding agents

titrmlib is a TUI framework for the TI-84 Plus CE, written in C for the CE
C toolchain (CEdev) on top of graphx. It is a sibling of Tincan and TINCLIB
(Wi-Fi/networking libraries for the same calculator, talking to an ESP board
over serial), and gives those and other CE apps composable UI pieces in place
of hand-written graphx code for every screen.

- Setup, building, tests and conventions: [CONTRIBUTING.md](CONTRIBUTING.md)
- Public API and usage: [README.md](README.md), [`src/titrm.h`](src/titrm.h)
- Planned work, known issues, out-of-scope items: [ROADMAP.md](ROADMAP.md)

## Core rules

- titrmlib owns the whole screen for one program, like curses. It renders the
  UI, reads the keypad and runs the loop. Apps never call graphx directly;
  keep everything behind the panel/widget API in `titrm.h`.
- `term_panel_print` and every other panel output must stay inside the
  panel's content area, at any depth in the tree.
- No FontLib, and no graphx text routines. `gfx_SetFontData` is fixed at an
  8 px advance, which would lose the narrow grid.

## Architecture

| File | Role |
|---|---|
| `src/titrm.h` | The public API |
| `src/titrm.c` | Cell grid, glyph drawing, panel tree, layout, focus, key translation, run loop |
| `src/titrm_widgets.c` | Text, list, input, log and progress widgets |
| `src/titrm_internal.h` | Panel and context structs, shared by the two `.c` files |
| `src/titrm_font.c`, `titrm_chars.h`, `FONT.md` | Generated by `tools/gen_font.py`; never edit by hand |
| `docs/` | API reference generated from the doc comments in `src/titrm.h` by Doxygen + moxygen (`make docs`); never edit by hand. Every public declaration needs a `/** */` comment inside its section's `@defgroup`; regenerate after changing the header |

- **Grid:** 5×7 glyphs in 6×8 cells give 53×30 cells, centered on the
  320×240 screen. Each frame, the panel tree is rendered into `grid` from
  scratch and compared with `shown`, and only changed cells are drawn.
- **Glyph drawing:** `draw_cell` writes into `gfx_vbuffer` directly, copying
  each cell row from `row_pixels`, a 64-entry table of 6-pixel patterns in
  the two fixed colors. Box-drawing characters and `TERM_CH_BLOCK` stretch
  into the gaps between cells so lines join up.
- **Characters:** 0x20–0x7E are ASCII. 0x80–0xFF hold box-drawing
  characters and icons, named `TERM_CH_*` (as characters) and `TERM_S_*`
  (as string literals).
- **Panels:** a fixed pool of `TERM_MAX_PANELS`. `term_split` sizes are
  `TERM_FIXED`, `TERM_PERCENT`, `TERM_FILL` and `TERM_FILL_WEIGHT`. Fixed and
  percent sizes are taken first, then fill panels share the rest by weight,
  with the rounding remainder on the last one. All children of a panel share
  one direction.
- **Layout** runs only when the tree changes (split, destroy, show/hide,
  border), via `layout_dirty`. It stores each panel's outer rect (`x y w h`)
  and content rect (`ix iy iw ih`). `term_put` and `term_panel_putc` read the
  content rect for every character.
- **Focus** moves in tree order (parents first, siblings in split order,
  wrapping) and skips hidden or zero-sized panels. `[vars]` is `TERM_KEY_TAB`.
- **Loop:** `term_run` blocks until `term_quit`. Each pass polls
  `os_GetCSC()`, lets the focused widget handle the key before the app's
  update callback, fires ticks from `clock()`, and redraws after any event.
  `os_GetCSC()` holds one key press between polls and repeats held keys.

## Performance on the eZ80

Code that is cheap on a desktop can be slow here:

- `int` is 24 bits. Multiplies by non-constants and many shifts compile to
  library calls (`__imulu`, `__bshl`). Hot paths use row-pointer tables and
  `uint8_t` arithmetic to avoid them.
- Every graphx call has noticeable overhead; drawing a cell with graphx
  primitives cost about 1 ms.
- Check the generated assembly in `obj/<program>/lto.s` when a hot path is slow.

Frame times are measured by the `perf` hardware test, which fails if they grow
by about 25%:

| Frame | Emulated time |
|---|---|
| Nothing changed, full screen of text rebuilt | ~76 ms |
| One row changed | ~105 ms |
| Every cell changed | ~400 ms |

Long frames make keys get lost: with `os_GetCSC`, two presses in one frame
count as one. The `widgets` hardware test runs at the autotester's default key
speed, so it catches a slowdown that brings this back.

## Testing

Details are in [CONTRIBUTING.md](CONTRIBUTING.md). In short:

- Unit tests (`make -C tests`) build the library natively against
  `tests/stubs/`, where `gfx_vbuffer` is an in-memory framebuffer.
  `test_titrm.c` includes `titrm.c` directly so it can read the grid.
- Hardware tests (`make hw-test`, needs `AUTOTESTER_ROM`) run in CEmu's
  `cemu-autotester` and use nothing else to drive the emulator. When a change
  alters screens on purpose, re-record with `make hw-record` and open the
  PNGs before trusting the new CRCs.
- New library behavior needs a unit test. Changes to rendering, input or
  timing should also be run through the hardware tests.
